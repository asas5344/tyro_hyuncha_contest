# 실제 3D 운전석 작업

작업 브랜치: `feature/realistic` (기준 `feature/first-person`, `611de13`). 원본 작업 폴더는 그대로 보존하고 별도 worktree에서 작업한다.

## 실제 운전석 시야 수정

기존/3D 운전석 비교 선택을 제거하고 기존 운전석의 정면(0도/하향 2도/FOV 56도), 좌우 확대 계산, 전환 속도와 미니맵을 재사용한다. TextureView 초기 콜백의 레이아웃 크기를 축소 버퍼 크기로 잘못 사용해 화면이 잘리던 결함을 수정했다. 최초 프레임 준비는 실제 TextureView 표시를 기준으로 판단한다.

터미널에서 별도 실행한 Pleos API34에서 실제 홈→주차 화면의 정면·우측·복귀, 전후진·회전, 백그라운드 복귀와 3회 재진입 계측 테스트가 통과했다. 단위 테스트 68개도 통과했다. 실제 캡처는 `verification/driver-fix/`에 있다. 지속 프레임률과 모든 차종×모든 모드의 최신 화면 검증은 별도다.

## 공통 실내 2차 업데이트

실내는 `cockpit.glb` 하나를 공유하고 차종별 눈높이에 맞춰 장착한다. `generate_cockpit.py`로 외형과 별도로 재생성한다. 기존 외형 GLB에 들어 있던 구형 실내는 렌더 대상에서 제외한다. 공통 실내 루트는 내 차 루트의 자식으로 연결하며 핸들 회전 노드도 공통 실내의 것을 사용한다.

눈높이는 아반떼 1.15m, 그랜저 1.18m, 투싼 1.38m, 싼타페 1.47m이며 게임 제작값이다. 정면 시야각은 64도다. 곡면 대시보드와 도어, 송풍구, 콘솔, 발밑 구조, 핸들 및 화면 하우징을 제작했다. 디버그 APK 및 단위 테스트 64개, 실내 구조 검사를 통과했고, 네 차종의 정면·좌·우를 Filament Metal로 렌더했다. 검수용 렌더에는 동적 계기판과 미러 영상이 없으며, 최신 Android 화면과 주행 검증은 별도로 남아 있다.

```sh
python3 tools/generate_cockpit.py
python3 tools/check_cockpit.py
```

## 현재 연결된 내용

- 아반떼·그랜저·투싼·싼타페에 각각 별도 GLB와 카메라 프로필이 있고 Filament 3D 운전석이 기본으로 열린다. 기존 운전석·탑뷰는 비교용으로 유지한다. 모델이 없는 차종·변형 제원에는 기존 화면을 사용한다.
- `ParkingSimulator`의 이동·조향·브레이크·충돌·주차 성공·채점은 변경하지 않는다. `sceneOf`가 실시간 주행과 다시 보기의 동일한 상태를 3D에 전달한다.
- 좌표 단위는 m. 시뮬레이터 `(x, y)`를 glTF `(X, Z)`로 옮기며 `Y`는 높이다. 원점은 뒷바퀴 축, +X는 차 전방, +Z는 우측이다.
- 기존 맵의 주차선·목표 칸·경계벽·주변 차량에서 장면을 생성한다. 충돌 데이터 없는 기둥·연석·주차턱을 새 장애물로 추가하지 않는다.
- 코드로 재생성하는 네 차종 GLB에 차체·창문·휠·램프·미러 외형·실내·핸들이 들어 있다. 객실은 속이 비어 있고 핸들은 대시보드 앞에 놓인다. 세단과 SUV의 보닛·지붕선·후면 형상·차체 높이는 각각 구성하며, 휠 아치도 메시로 만든다. 차종별 실내 디자인 복제는 하지 않고 공통 실내를 조정한다.
- 앞바퀴 조향, 바퀴 회전, 핸들 회전을 별도 노드로 갱신한다. 주행 조향으로 고개가 돌지 않는다. 좌우 버튼은 실제 미러 위치를 바라본다.
- 좌·우·룸미러는 별도 카메라를 낮은 해상도로 그려 실제 거울 면에 표시하는 코드를 연결했다. 화면 면을 별도 레이어로 분리해 미러 재귀를 차단한다.
- 후진 시 `CarCamera`에 따라 후방 카메라 또는 서라운드 뷰를 실내 화면에 표시한다. 화면을 확대하고 운전석으로 복귀하는 버튼도 있다.
- 실내 계기판에는 속도·D/R을 텍스처로 표시한다. 다시 보기에도 실제 속도를 저장해 동일한 계기판 값을 사용한다. 이동·충돌 수식은 변경하지 않고 기록 데이터에 속도 필드를 추가했다.
- 진행선은 `Guidance.predictPath`를 그대로 사용한다. 차량 위치는 루트 변환으로 움직이고 조향·진행 방향이 바뀔 때만 고정 버퍼의 메시를 갱신한다.
- 전방 해상도 상한은 960×720, 렌더 요청은 약 30Hz, 미러는 10Hz다. 시야에 들어오는 미러만 갱신하고, 차량·시점·계기판 변화가 없으면 3D 재렌더링을 건너뛴다. 정적 메시와 휠 스포크를 재질별로 합쳐 세단은 49노드, SUV는 48노드로 줄였다. 이는 설정과 구조 최적화이며 측정된 30fps 보장은 아니다.
- 화면 이탈·백그라운드에서 렌더 콜백을 중단한다. swap chain·뷰·카메라·텍스처·재질·GLB·엔진은 소유 객체에서 해제한다.

## 재생성 및 빌드

```sh
python3 tools/generate_sedan.py
python3 tools/check_models.py
python3 tools/check_sedan.py
MATC=/path/to/filament-1.66.0/bin/matc tools/build_materials.sh
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest
```

Filament Android와 gltfio는 둘 다 `1.66.0`으로 고정한다. `1.77.3`은 Kotlin stdlib 2.4를 가져와 현재 Kotlin 2.2.10과 충돌했다. 재질 컴파일러도 반드시 같은 1.66.0 릴리스를 사용한다. 컴파일된 `.filamat`과 GLB를 포함하므로 일반 Android 빌드에는 matc나 Python이 필요 없다.

- [공식 Filament 1.66.0 도구](https://github.com/google/filament/releases/tag/v1.66.0)
- [Filament 공식 문서](https://google.github.io/filament/dup/intro.html)

모델 전장·전폭·휠베이스·뒤 오버행은 `CarSpec.kt`를 읽어 생성하며 기존 충돌 사각형에 맞춘다. 그랜저는 5.035×1.880m, 휠베이스 2.895m이다. 눈높이·지붕 높이·미러 위치는 게임 화면을 위한 제작값이며 실제 제조사 실내 제원을 주장하지 않는다. `vehicle_visuals.json`과 `VehicleVisuals.kt`도 같은 제작 코드가 출력한다. 미러 돌출부는 기존 시뮬레이터와 같이 차체 충돌 범위에 포함하지 않는다. 주변 차량은 맵의 기존 4.8×1.86m 사각형에 맞춰 같은 GLB를 인스턴싱한다.

## 검증 기록 (2026-11-07)

- 디버그 APK 및 Android 계측 테스트 APK 빌드 성공.
- 단위 테스트 64개 통과: 기존 판정·주차 방식·다시 보기, 좌표·차체 모서리 일치, 미러·후방·탑뷰 카메라 방향, 시야 판별·진행선 버퍼·차종 프로필·재생 속도 기록을 포함한다.
- GLB 구조·유효 좌표·차체 치수·뒷바퀴 축 기준 회전 중심 검증 통과.
- 미러 추가 전의 첫 3D 버전은 Pleos API 34 에뮬레이터에서 실제 표시·전후진·회전·백그라운드 복귀·3회 화면 재진입 계측 테스트 1개를 통과했다.
- 소프트웨어 GPU 모드는 약 1fps로 느렸다. Mac GPU 모드에서도 짧은 계측 구간만 확인했으며 지속 30fps는 검증하지 않았다.
- 이후 추가한 네이티브 미러/후방 렌더 타깃·진행선·계기판·다른 세 차종·메시 통합은 컴파일·수학/데이터 테스트까지만 완료했다. 사용자의 Mac 부하 요청으로 에뮬레이터는 종료했고 다시 실행하지 않았다. 실제 화면의 텍스처 상하·좌우 방향, 미러 시야, 자원 해제와 성능은 다음 Android 실행에서 확인해야 한다.

아이패드 웹 미리보기 실험은 사용자가 취소했다. Android 작업은 웹에 의존하지 않는다. 주행 데이터 내보내기용 임시 테스트는 제거했다.

## 다음 실행에서 확인할 항목

- 미러의 화면 방향·내 차 옆면·경계 위치와 후방 화면의 조향 방향.
- 미러가 반복해서 비치지 않는지, 후진↔전진·후방 화면 확대·기존 화면 전환·다시 보기의 동일 좌표.
- 화면 재진입·랜덤 맵 재시작·백그라운드 전환 후 검은 화면, 종료, 메모리 증가 여부.
- 실제 차량 P단 잠금·브레이크 준비 상태·버튼 입력과 3D 화면 조작.
- 네 차종 각각의 실내 구도와 차체·충돌 치수 일치. 모델 생성 검증은 통과했으나 최신 모델의 Android 화면 검증은 남아 있다.
- 새 계측 테스트는 네 차종×세 주차 방식에서 실제 텍스처가 검은 화면이 아닌지, 후방/서라운드 화면 전환이 실제로 바뀌는지 검사하도록 준비했다. 사용자 Mac에서는 실행하지 않았다.
